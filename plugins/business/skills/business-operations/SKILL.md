# Business Operations

Start from the current project and commitment records; distinguish missing updates from verified delays. Maintain an operating review with outcome, owner, due date, evidence, blocker and next decision for each workstream. Use Notion as the shared decision record and Microsoft 365 tasks/calendar for accepted commitments.

For a recurring review, compare changes since the last reviewed snapshot and report only material changes. Separate decisions from observations and proposals. A system-health failure is an engineering assignment; hand its observed symptoms and acceptance criteria to engineering rather than opening production shell access.

Create or update external records through the approved tools and retain their receipts. Use stable record IDs to avoid duplicates after interrupted runs. Report blocked dependencies explicitly; never mark a task complete from an agent's claim alone.
